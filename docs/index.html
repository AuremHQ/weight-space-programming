Our vision

Big AI should not belong only to the people who can pay for big models. A small model running on your own machine should still perform at its best — and everyone should have the right to the best experience and the best results.

"This kit is free for everyone, and it stays free. A small model should not mean bad results — everyone has the right to the best experience and the best results. The team's vision is simple: everyone should benefit from this kit." — Tejinder Sandhu, founder of Aurem (LinkedIn)

wsp-kit is our first step toward that vision: a free, open-source tool that tries to fix a small model's specific failure by editing its weights directly — no retraining, no fine-tuning, no gradients, no cloud bill. If the numbers do not improve, nothing ships. The kit is honest about what it can and cannot do, and the proof is published below.

How it works

wsp-kit follows the weight-space programming idea from "Sparks of Weight-Space Programming" — a research blog post by the MIT CSAIL team (published 2026-11-02; a blog post, not a peer-reviewed paper, and not yet independently replicated). The idea: a model's failure can live in a small set of weights. Find those weights, change them a little, and the failure can go away — without retraining the model.

0

Cheap fix first

Before touching any weight, the kit tries the free knobs — temperature first. If a setting fixes it, no edit is needed.

1

Detect

Measure the failure, then prove the cause: disable the suspected weights and check whether the failure disappears. The bar is +5 points — no proof, no edit.

2

Fix

Subtract the failure direction from the MLP output columns — under 1% of the model's weights, at most 3 attempts. The original weights are never overwritten.

Then the eval gate re-runs the same prompts with the same settings. Only a gate-passing edit ships. The full rules live in SKILL.md.

The eval gate

The gate is the whole point. An edit ships only if all of these hold:

  • The failing metric improves by at least 5 points.
  • Guards and neighbours regress by no more than 2 points.
  • The result holds at serving temperature and greedy (0.0).

Gate fail = nothing ships. A gate that only says yes is not a gate. Our status page shows only gate-passing runs — no red, no failures on display — while the full honest log stays in REAL-RUNS.md.

Try it — easy mode

One command installs the skill and the kit, sets up the wsp command, and runs the demo automatically — so you see a result in seconds, with nothing to configure.

curl -fsSL https://raw.githubusercontent.com/AuremHQ/weight-space-programming/main/install.sh | bash

After install, the demo has already run and shown its result. Then one command fixes your own model — it asks 4 simple questions (which model, what goes wrong, what goes right, what should not change), builds the test file, runs the pipeline, and shows the result:

wsp auto

See the result on the status page:

wsp serve

Keep it improving in the background, and serve the same model with its weights updated live — no reload, no swap:

wsp loop --model Qwen/Qwen3-0.6B --watch-dir ./evals-incoming --out-dir ./wsp-loop-out
wsp serve-model --model Qwen/Qwen3-0.6B --versions-dir ./wsp-loop-out

If the kit helped, please star the repo — it helps others find it.

Commands

  • wsp auto — easy mode: 4 questions, then the kit runs by itself.
  • wsp demo — run the pipeline test end to end.
  • wsp run — run the full gated pipeline on your own small model.
  • wsp watch — keep watching a folder; every new eval file runs automatically.
  • wsp loop — keep improving in the background; new failures become new versions.
  • wsp serve-model — serve one model; new passing edits override its weights live, same model, no swap.
  • wsp status — show only gate-passing runs (wins only).
  • wsp serve — a live status page on your machine (default port 8899).

Rules the kit will not break

  • Small open-weight models only — up to 3B parameters. Closed API models (ChatGPT, Claude) are refused: their weights are never in your hands.
  • No invented evaluations — you supply the prompts that define success.
  • No adding abilities — only removing a diagnosed obstacle.
  • No production-branch edits, no safety removal.

Questions, answered

What is wsp-kit?

wsp-kit by Aurem is a free, open-source engineering tool for small models. It tries to fix one specific, repeatable failure in a small open-weight model by editing its weights directly — no retraining, no fine-tuning, no gradients.

Does wsp-kit fix real models?

Not yet. The pipeline test passed (failing 64.14 → 75.43, +11.29), but all four real-model runs (Qwen3-0.6B three times — run 1, run 2, and a clean re-run — plus GPT2-124M) failed the eval gate, so 0 weights shipped. The numbers are published in REAL-RUNS.md.

How do I try wsp-kit?

One command installs the skill: curl -fsSL https://raw.githubusercontent.com/AuremHQ/weight-space-programming/main/install.sh | bash. Then run wsp demo for the pipeline test or wsp run on your own small model.

Is wsp-kit free?

Yes. Free for everyone, MIT licensed. A small model should not mean bad results.

What is the eval gate?

The eval gate re-runs the same prompts with the same settings after an edit. The edit ships only if the failing metric improves by at least 5 points with no more than 2 points regression on guards and neighbours, at serving temperature and greedy. If the numbers don't improve, nothing ships.

Which models does wsp-kit support?

Small open-weight models up to 3B parameters that you control. Closed API models (ChatGPT, Claude) are refused — their weights are never in your hands.

Can it make my model smarter?

No. Editing removes obstacles — it cannot add abilities. MIT's Gemma 3 270M control model could not be improved at all. If the failure is a missing ability rather than a blocked one, the kit refuses.

What happens if the gate fails?

Nothing ships. The report is saved, the original weights are untouched, and the run is logged in REAL-RUNS.md. Our real-model runs all ended this way so far — and we publish them anyway.

Does it work on ChatGPT or Claude?

No. Those are closed API models — their weights are never in your hands, so there is nothing to edit. wsp-kit works on small open-weight models you can download and run yourself.
